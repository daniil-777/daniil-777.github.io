# Portfolio security review · 6 October 2026

The public Ask AI assistant is temporarily paused in both the published interface and its Cloudflare backend. The backend rejects requests with HTTP 503 before reading a question, loading knowledge, touching budget/rate bindings, or calling a model. Only the exact server setting `CHAT_ENABLED="true"` can enable it; absent or malformed values remain closed. `DAILY_LIMIT="0"` adds an independent spending guard. Re-enabling requires an intentional frontend and backend change and a new review.

Disabled native buttons replace every public Ask AI trigger, including mobile navigation and `/ask/`. The dialog is excluded, the lazy loader returns early, and the exported opener also returns early. Static portfolio answers and contact links remain available. The watch's reviewed sentences and local retrieval run on the visitor's device and do not call a paid AI service.

## Audit findings and changes

- Updated the single dependency finding, `http-cache-semantics` 4.2.0 → 4.3.0, without changing Astro or other packages. Current full npm audits for both the site and worker report zero known vulnerabilities. Production dependency audits now gate every GitHub deployment. This is an advisory check, not proof that code has no vulnerabilities. See the [upstream advisory](https://github.com/advisories/GHSA-ch52-4w7c-c8xp).
- Enforced Content Security Policy at demtsev.com and its www redirect. Scripts use same-origin files and three exact SHA-256 hashes for trusted built inline bodies. Inline event handlers, arbitrary inline scripts, general JavaScript eval, objects, forms and base URL overrides are disallowed. The pinned, integrity-checked TensorFlow runtime URLs are permitted only on the four architecture/drawings preview document routes. A build gate rejects unreviewed inline script changes.
- Added `nosniff`, `Referrer-Policy: no-referrer`, capability restrictions, and same-origin framing protections; retained one-year HTTPS HSTS. Same-origin preview frames remain supported. Images allow local data/blob exports; media and model fetches stay same-origin. Inline styles remain permitted for existing layout and interactive resizing. [Cloudflare security-header guidance](https://developers.cloudflare.com/workers/examples/security-headers/) explains the delivery mechanism.
- Added edge throttling of 300 requests per minute per IP, with 429 and Retry-After before origin access. A failed rate binding returns a generic 503. [Cloudflare's native limiter](https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/) is per location and eventually consistent; it is not a global accounting or billing limit. The separate closed AI gate controls spending.
- Blocked common hidden-source/configuration probes, including encoded paths, `.git`, `.env`, worker/source trees and common exploit endpoints. Unknown hosts and non-read methods are rejected. Responses, redirects and generic failures all receive security headers. The fixed GitHub origin receives only an explicit safe header allowlist; visitor cookies and Authorization are not forwarded, and upstream Set-Cookie is stripped.
- Reviewed browser rendering and restored chat resources: questions and model output use text nodes; stored resource links are validated. No obvious private source/configuration files or API-key patterns were found in the generated public build. No credential values were printed or committed.

## Validation and scope

Source-bound automated evidence is in `site-security-review.json` and the watch review. Tests cover disabled requests with missing, malformed, legitimate and forged origins; no service calls or body reads; source probes; CSP scope; rejected methods; rate exhaustion and binding failure; redirects; private header stripping; HEAD/range preservation; generic upstream errors; and frozen rendered assistant triggers. Browser checks exercise the disabled interface, theme, mobile menu, QR export, videos, the ticker and the neural preview runtimes using isolated software WebGL (32-unit architecture resolution; no general JavaScript eval allowance), plus rejection of an untrusted inline script and handler.

This review concerns the portfolio source, current dependency advisories, the public assistant endpoint and the Cloudflare delivery worker. It uses benign requests to owned endpoints and mocked exhaustion tests, not a traffic flood or an external penetration-testing service. Cloudflare account login security, recovery settings and unrelated infrastructure were not audited. Physical-device and non-Chromium behavior are not established by desktop browser emulation. The GitHub Pages origin remains publicly readable; the stronger response-header policy applies to demtsev.com. Further security depends on keeping dependencies and the delivery policy maintained.
